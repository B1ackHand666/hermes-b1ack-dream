# Hermes 适配指南

在写任何 Hermes 专用代码前，针对目标安装/源码完成并记录以下检查：

1. Provider 接口、插件注册方式、版本范围和配置加载位置；
2. Provider Memory 的会话注入位置、长度限制及异常处理；
3. 每轮消息、回答前、回答后和会话结束 hook 的真实可用性；
4. 会话 ID、消息 ID、会话标题、最终上下文使用状态能否可靠获得；
5. `USER.md` / `MEMORY.md` 的真实路径、读取/写入约束、长度限制和生效时机；
6. Hermes 当前 WebUI/API、日志、测试、构建和用户数据目录规则。

然后创建一个很薄的版本化适配器，将真实 hook 映射到 `HermesMemoryProvider`。该适配器必须：

- 在 Provider 不可用时降级为空上下文，不丢失已有数据；
- 只在真实存在的 hook 上记录 Capture、Recall 和 Usage；
- 将无法知道“最终是否进入上下文”的状态明确记录为限制，而不是伪造 `true`；
- 不修改 Hermes 核心，也不尝试同步、读取后写回或自动编辑 `USER.md` / `MEMORY.md`；
- 将已验证的版本、证据、限制和回归测试结果写入此文档的后续兼容性记录。

当前仓库未包含 Hermes 源码或安装目录，因此没有声明任何具体 Hermes 版本兼容性。
